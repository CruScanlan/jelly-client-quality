## 3. Plugin anatomy

Minimum: one class library targeting `net10.0`, referencing `Jellyfin.Controller` (and `Jellyfin.Model` / `Jellyfin.Common` as needed), with:

| Piece | Purpose | Notes / source |
|---|---|---|
| `PluginConfiguration : BasePluginConfiguration` | Settings POCO | Serialised to XML at `<data>/plugins/configurations/<AssemblyName>.xml` ([`BasePluginOfT.cs:131`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/MediaBrowser.Common/Plugins/BasePluginOfT.cs#L131), name override at `ConfigurationFileName`) `[V]` |
| `Plugin : BasePlugin<PluginConfiguration>` | Entry class: `Name`, `Id` (GUID), ctor `(IApplicationPaths, IXmlSerializer)` | [template Plugin.cs](examples/template/Plugin.cs). Every official plugin keeps a static `Instance` to reach `Configuration` from DI-created classes. Config is lazily loaded; `UpdateConfiguration` saves and raises `ConfigurationChanged` ([`BasePluginOfT.cs:171`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/MediaBrowser.Common/Plugins/BasePluginOfT.cs#L171)) `[V]` |
| `IHasWebPages` (on `Plugin`) | Declares embedded HTML/JS pages for the Dashboard | [`IHasWebPages.cs:9`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/MediaBrowser.Model/Plugins/IHasWebPages.cs#L9), `PluginPageInfo` fields: `Name`, `DisplayName`, `EmbeddedResourcePath`, `EnableInMainMenu`, `MenuSection`, `MenuIcon` `[V]` |
| `IPluginServiceRegistrator` | Parameterless class; adds services to DI | [`IPluginServiceRegistrator.cs:18`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/MediaBrowser.Controller/Plugins/IPluginServiceRegistrator.cs#L18) |
| `build.yaml` | Metadata for JPRM packaging (name, guid, version, targetAbi, framework, artifacts…) | [template build.yaml](examples/template/build.yaml) |

Loading: the server scans `<data>/plugins/*/`, loads every DLL in a folder into a per-plugin `AssemblyLoadContext`, calls `assembly.GetTypes()` and, on `TypeLoadException`/`ReflectionTypeLoadException`, marks the plugin `NotSupported` (version mismatch with shared Jellyfin libs); other load failures → `Malfunctioned` ([`PluginManager.cs:175`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Emby.Server.Implementations/Plugins/PluginManager.cs#L175)) `[V]`. The template marks the Jellyfin package refs `ExcludeAssets=runtime` (its README: skipping it "will prevent your plugin from registering correctly") so the server's own assemblies are used; newer official plugins (transcodekiller, opensubtitles) omit it and rely on `artifacts:` in `build.yaml` listing only the plugin DLL `[V for the files; I for why both work]`.

`targetAbi` semantics: a plugin is loaded only if `server version >= targetAbi` ([`PluginManager.cs:755`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Emby.Server.Implementations/Plugins/PluginManager.cs#L755); catalog filter at [`InstallationManager.cs:137`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Emby.Server.Implementations/Updates/InstallationManager.cs#L137)) `[V]`. It is a *minimum*, not a compatibility range, so a plugin built for 10.11 still "loads" on 12.x and can fail with `NotSupported` at type load `[I]`. Rebuild per major (official repo ships separate 10.11 and 12.0 builds: [live manifest](https://repo.jellyfin.org/files/plugin/manifest.json)).

Official-plugin patterns worth copying are in [examples/](examples/README.md): template skeleton, `transcodekiller` (hosted service + session event + config page — closest to this project), `sessioncleaner` (`IScheduledTask`), `webhook` (`IEventConsumer<T>` registration), `opensubtitles` (authorised API controller).

## 4. Build, install, package, distribute

**Dev loop (manual)** — build, copy the plugin DLL(s) (+ `.pdb` for debugging) into `<data>/plugins/<PluginName>/`, restart server ([template README §4, §6](https://github.com/jellyfin/jellyfin-plugin-template/blob/c93225a0a5a76d3843db05b4b5b77fcfc482fba3/README.md)) `[V]`. A folder without `meta.json` is auto-registered: name = folder name, version parsed from a `_x.y.z.w` suffix else the server version, `TargetAbi` = server version ([`PluginManager.cs:759`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Emby.Server.Implementations/Plugins/PluginManager.cs#L759)) `[V]`. Data dir defaults: `/var/lib/jellyfin` (packaged Linux), `%LOCALAPPDATA%\jellyfin` (Windows direct), `${XDG_DATA_HOME}/jellyfin` (dev; see template `.vscode/settings.json`) ([docs](https://github.com/jellyfin/jellyfin-docs/blob/bd15bcac098f6b22517bae83a2e6e891f2a54f7d/general/server/plugins/index.md)). The template's `.vscode` tasks (publish → mkdir → cp) automate this and launch the server from `../jellyfin/Jellyfin.Server`.

**Catalog install** — `InstallationManager` downloads `sourceUrl`, verifies an **MD5** of the zip against `checksum` ([`InstallationManager.cs:586`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Emby.Server.Implementations/Updates/InstallationManager.cs#L586)), extracts to `plugins/<Name>_<version>/` ([`InstallationManager.cs:598`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Emby.Server.Implementations/Updates/InstallationManager.cs#L598)) and writes `meta.json` (`PluginManifest`: category, changelog, description, guid, name, overview, owner, targetAbi, timestamp, version, status, autoUpdate, imagePath, assemblies — [`PluginManifest.cs:1`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/MediaBrowser.Common/Plugins/PluginManifest.cs#L1)) `[V]`.

**Repository manifest** — a JSON array of plugins; each has `guid, name, description, overview, owner, category, [imageUrl]` and `versions[]` with `version, changelog, targetAbi, sourceUrl, checksum, timestamp` ([blog post](https://jellyfin.org/posts/plugin-updates/); real example fetched from [repo.jellyfin.org manifest](https://repo.jellyfin.org/files/plugin/manifest.json), entry "Transcode Killer": `targetAbi 12.0.0.0`, zip at `repo.jellyfin.org/files/plugin/transcode-killer/transcode-killer_5.0.0.0.zip`, 32-hex checksum) `[V]`. Users add third-party repos in Dashboard → Plugins → Repositories; official URLs: stable `https://repo.jellyfin.org/files/plugin/manifest.json`, unstable `.../plugin-unstable/manifest.json` ([docs](https://jellyfin.org/docs/general/server/plugins/)). The 2020 blog's `releases/plugin/manifest-stable.json` and `releases/plugin/manifest.json` URLs returned byte-identical content to `files/plugin/manifest.json` on 2026-10-06 `[V]`; the server also seeds a default repository via migrations ([`20250420170000_UpdateDefaultPluginRepository.cs`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Jellyfin.Server/Migrations/Routines/20250420170000_UpdateDefaultPluginRepository.cs)). Hosting is arbitrary (GitHub release assets + a manifest file works).

**Packaging tool** — official CI uses **JPRM** (`jprm`, [oddstr13/jellyfin-plugin-repository-manager](https://github.com/oddstr13/jellyfin-plugin-repository-manager), MPL-2.0; PyPI `jprm`) via reusable workflows in [`jellyfin/jellyfin-meta-plugins`](https://github.com/jellyfin/jellyfin-meta-plugins/tree/5ebf9f9455736773ab6f94cdb19fb903ece41b83/.github/workflows) (`build.yaml`, `publish.yaml`, inputs `dotnet-version: 10.0.x`, `dotnet-target: net10.0`). The template's workflows just `uses:` these. JPRM reads `build.yaml`, runs `dotnet publish`, zips the listed `artifacts`, and `jprm repo add` updates the manifest. Version scheme: 4-part (`5.0.0.0`) in `build.yaml` and `Directory.Build.props` ([template](examples/template/Directory.Build.props)) `[V]` for the files; JPRM internals `[I]`.

NixOS note `[U]`: plugin dirs under `/var/lib/jellyfin/plugins` are mutable state; the Nix `services.jellyfin` module's handling of declarative plugins was not researched.

## 5. Configuration pages

- Pages are **embedded resources** (`<EmbeddedResource Include="Configuration\configPage.html" />`) registered via `IHasWebPages.GetPages()`; served by `GET /web/ConfigurationPage?name=<Name>` ([`DashboardController.cs:73`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Jellyfin.Api/Controllers/DashboardController.cs#L73)); list via `GET /web/ConfigurationPages` (admin only; `enableInMainMenu` filter) `[V]`. A plugin can register several pages and also `.js` files (mime by extension) — see opensubtitles (`opensubtitles.html` + `opensubtitlesjs`) ([OpenSubtitlesPlugin.cs](https://github.com/jellyfin/jellyfin-plugin-opensubtitles/blob/60d2c74d4e8bbee738fa88288fa5c583036c4183/Jellyfin.Plugin.OpenSubtitles/OpenSubtitlesPlugin.cs)) `[V]`.
- The page is an HTML fragment (`data-role="page" class="... pluginConfigurationPage" data-require="emby-input,emby-button,..."`) hosted inside the admin Dashboard SPA. Load/save with the global `ApiClient.getPluginConfiguration(guid)` / `updatePluginConfiguration(guid, config)` (config JSON uses the C# property names, PascalCase) and `Dashboard.showLoadingMsg()/processPluginConfigurationUpdateResult` ([template configPage.html](examples/template/Configuration/configPage.html)) `[V]`.
- `EnableInMainMenu=true` adds a Dashboard drawer entry (`MenuSection`, `MenuIcon`, `DisplayName`) ([`PluginDrawerSection.tsx:18`](https://github.com/jellyfin/jellyfin-web/blob/61b1f890365ad15138e943e694af723c1d47df2a/src/apps/dashboard/components/drawer/sections/PluginDrawerSection.tsx#L18)) `[V]`.
- Underlying REST: `GET/POST /Plugins/{id}/Configuration`, whole controller `[Authorize(Policy = RequiresElevation)]` ([`PluginsController.cs:25`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Jellyfin.Api/Controllers/PluginsController.cs#L25), `:164`, `:188`) `[V]` → **non-admin users cannot use these endpoints**.
- **Config pages are Dashboard-only.** `IHasWebPages` is consumed only by `DashboardController` ([`DashboardController.cs:104`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Jellyfin.Api/Controllers/DashboardController.cs#L104)); there is no official extension point for injecting UI into the end-user player/settings screens `[V]` (that no other consumer exists: grep of server source at v12.2). Web client "plugins" are a separate, client-side mechanism (`plugins` array in the web `config.json`, loaded by `getPlugins()`; [`webSettings.js:109`](https://github.com/jellyfin/jellyfin-web/blob/61b1f890365ad15138e943e694af723c1d47df2a/src/scripts/settings/webSettings.js#L109), [`config.json:34`](https://github.com/jellyfin/jellyfin-web/blob/61b1f890365ad15138e943e694af723c1d47df2a/src/config.json#L34)) and are controlled by whoever hosts jellyfin-web, not by server plugins `[V]`.

## 6. DI / service registration

- `IPluginServiceRegistrator.RegisterServices(IServiceCollection, IServerApplicationHost)` is instantiated with `Activator.CreateInstance` (needs a parameterless ctor) for each enabled+supported plugin; exceptions mark the plugin `Malfunctioned` ([`PluginManager.cs:206`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Emby.Server.Implementations/Plugins/PluginManager.cs#L206)) `[V]`.
- It runs **after** the server's own `RegisterServices` ([`ApplicationHost.cs:492`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Emby.Server.Implementations/ApplicationHost.cs#L492)) and into the same collection the ASP.NET host uses (`.ConfigureServices(services => appHost.Init(services))`, [`Program.cs:180`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Jellyfin.Server/Program.cs#L180)) `[V]`. Consequences `[I]`: standard MS-DI "last registration wins" lets a plugin replace/decorate core services; `services.Configure<MvcOptions>(...)`, `IStartupFilter`, `IConfigureOptions<>` registered here are honoured by the web host. Replacing core singletons is brittle across versions.
- Register: hosted services (`AddHostedService<T>()`), `IEventConsumer<T>`, `IScheduledTask` (auto-discovered, not required in DI), HttpClients, your own singletons. **The main `Plugin` class must not implement `IHostedService`** (template README). Hosted services/consumers read settings via `Plugin.Instance.Configuration` (all official plugins) or subscribe to `Plugin.ConfigurationChanged` ([webhook entry point](https://github.com/jellyfin/jellyfin-plugin-webhook/blob/ede062d6106092b209d31adcf6d64b81a4be7013/Jellyfin.Plugin.Webhook/WebhookServerEntryPoint.cs)).
- Services you can constructor-inject (all in `Jellyfin.Controller`): `ISessionManager`, `IDeviceManager`, `IUserManager`, `ILibraryManager`, `IMediaEncoder`, `ITranscodeManager`, `IServerConfigurationManager`, `IAuthorizationContext`, `ILocalizationManager`, `ITaskManager`, `IEventManager`… (template README lists more).

## 7. API controllers in plugins

- Any concrete `ControllerBase` in a loaded plugin assembly is added as an MVC application part: [`ApplicationHost.cs:1010`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Emby.Server.Implementations/ApplicationHost.cs#L1010) (discovery) → [`ApiServiceCollectionExtensions.cs:160`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Jellyfin.Server/Extensions/ApiServiceCollectionExtensions.cs#L160) (`AddApplicationPart`), controllers resolved from DI (`AddControllersAsServices`) so constructor injection works `[V]`.
- Reference `Jellyfin.Common` (not just Controller): it carries `<FrameworkReference Include="Microsoft.AspNetCore.App"/>` ([`MediaBrowser.Common.csproj:17`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/MediaBrowser.Common/MediaBrowser.Common.csproj#L17)) and `MediaBrowser.Common.Api.Policies` (`RequiresElevation`, `SubtitleManagement`, `LocalAccessOnly`, …) `[V]`. - JSON is PascalCase (core configures `JsonDefaults.PascalCaseOptions` for MVC, [`ApiServiceCollectionExtensions.cs:140`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Jellyfin.Server/Extensions/ApiServiceCollectionExtensions.cs#L140)) `[V]`.

## 9. Events and hooks

Two mechanisms, both **post-hoc notifications** — neither can veto/alter playback decisions:

1. **`IEventConsumer<T>`** (`T : EventArgs`) registered in DI; `EventManager` resolves all consumers in a fresh scope and awaits them sequentially, catching/logging exceptions ([`EventManager.cs:52`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Jellyfin.Server.Implementations/Events/EventManager.cs#L52); interface [`IEventConsumer.cs:18`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/MediaBrowser.Controller/Events/IEventConsumer.cs#L18)) `[V]`. A slow consumer delays the publisher `[V by code reading]`. Event types: authentication, `SessionStarted/Ended`, `PlaybackStart/Stop` (and progress), plugin install/update, task completion, user created/updated/locked/password-changed, subtitle download failure — see the full registration list in [webhook PluginServiceRegistrator.cs](examples/webhook/PluginServiceRegistrator.cs) and consumer example [PlaybackStartNotifier.cs](examples/webhook/PlaybackStartNotifier.cs) (`PlaybackProgressEventArgs` carries `Users, Item, DeviceId, DeviceName, ClientName, PlaySessionId, Session`).
2. **CLR events on `ISessionManager`**: `PlaybackStart`, `PlaybackProgress`, `PlaybackStopped`, `SessionStarted/Ended/Activity`, `CapabilitiesChanged`, `SessionControllerConnected` ([`ISessionManager.cs:27`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/MediaBrowser.Controller/Session/ISessionManager.cs#L27), `:59`); subscribe in `IHostedService.StartAsync`, unsubscribe in `StopAsync` ([KillerEntrypoint.cs](examples/transcodekiller/KillerEntrypoint.cs)) `[V]`.

Neither `MediaInfoController` nor `MediaInfoHelper` publishes through `IEventManager` `[V]` (grep) — so PlaybackInfo is not observable/hookable via events.

## 10. Hooks relevant to per-client quality / forced transcoding

### 10.1 How the playback decision is made today `[V]`

1. ### 10.2 Existing per-device state in the server `[V]`

- `DeviceOptions` has only `CustomName` ([`DeviceOptions.cs:8`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/src/Jellyfin.Database/Jellyfin.Database.Implementations/Entities/Security/DeviceOptions.cs#L8); `IDeviceManager.UpdateDeviceOptions(deviceId, deviceName)` [`IDeviceManager.cs:102`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/MediaBrowser.Controller/Devices/IDeviceManager.cs#L102)). **No per-device bitrate/transcoding setting exists server-side.** A plugin must persist its own map (plugin config XML, or a file under `IPlugin.DataFolderPath`).

### 10.5 Suggested shape (inferred)

- Config (`PluginConfiguration`): list of rules `{DeviceId | Client match, MaxStreamingBitrate?, MaxHeight?(note: not enforced by PlaybackInfo bitrate alone), ForceTranscode}`; Dashboard config page lists known devices from `IDeviceManager.GetDevices` via a small admin API controller.
- End-user self-service UI is **not** possible through official plugin pages (§5); options: admin-managed rules only; a `[Authorize]` controller + a custom client-side script (unofficial); or a user-specific rule keyed by `User.Id`+`DeviceId`.
- Enforcement: hook A on PlaybackInfo (+ C for audio/static). Optional D for logging/"why transcoding" using `TranscodeReasons`.

## 11. Gotchas

- Template is stale (net9/10.11) — start from transcodekiller-style csproj (`net10.0`, `Jellyfin.Controller 12.*-*`) and `targetAbi 12.0.0.0`.
- Plugin must be rebuilt per Jellyfin major; wrong refs → `NotSupported` ([`PluginManager.cs:175`](https://github.com/jellyfin/jellyfin/blob/ca0f16eb7c195f720a1493ed469a27c4657db0c6/Emby.Server.Implementations/Plugins/PluginManager.cs#L175)).
- Server restart required to load/unload plugin code.
- Main plugin class cannot also be `IHostedService`; `Plugin.Instance` static pattern is idiomatic.
- Plugin config REST + config page are admin-only.
- Device capabilities are in-memory only (reset on restart); `DeviceId` is the stable key.
- GPL: the server repo's LICENSE is GPL-2.0 while published NuGet packages (what you link) are GPL-3.0-only — see [sources.md](sources.md). Don't paste server source into this repo; link it.
